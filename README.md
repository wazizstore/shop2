# Landing Page — وسادة حماية رأس وظهر الطفل (تصميم النحلة)

صفحة هبوط جاهزة للنشر، بـ HTML/CSS/JS فقط (بدون React)، متصلة بـ Google Apps Script و Meta Pixel، مع منع تكرار الطلبات ومنع إطلاق `Purchase` بشكل غير موثوق.

└── README.md

## 1) خطوات تحديث Google Apps Script وإعادة نشره (مع الحفاظ على رابط /exec)

الرابط الحالي المستعمل في `index.html`:

```
https://script.google.com/macros/s/AKfycbyILPWXzyTw6GUg7_8LwmqsDHqtzUdgQlnIw8EZPMKWfOAn3x-_gp22JZmFF6L6P48/exec
```

للحفاظ على نفس هذا الرابط بعد تحديث الكود، اتبع الخطوات التالية بالضبط:

1. افتح مشروع Apps Script المرتبط بجدول `Orders` (نفس المشروع القديم، **لا تنشئ مشروعاً جديداً**).
2. احذف محتوى `Code.gs` القديم، وألصق محتوى `gas/Code.gs` الجديد كاملاً.
3. تأكد أن `SPREADSHEET_ID` في الملف يطابق معرف الجدول الحقيقي:
   `1k1U86PtxqOCcutPHRGYbV65p9dLwn50SFm8-2A5L0J4`
4. احفظ المشروع (`Ctrl+S` أو أيقونة الحفظ).
5. من القائمة أعلى اليمين اضغط **Deploy / نشر → Manage deployments / إدارة عمليات النشر**.
6. اختر عملية النشر الحالية (Web app) التي يخرج منها الرابط `/exec` الحالي.
7. اضغط على أيقونة القلم (✏️ Edit) بجانبها.
8. في حقل **Version**، اختر **New version / نسخة جديدة**.
9. تأكد أن الإعدادات كما يلي:
   - **Execute as:** Me (حسابك)
   - **Who has access:** Anyone (حتى يعمل الفورم بدون تسجيل دخول)
10. اضغط **Deploy / نشر**.
11. **رابط `/exec` يبقى كما هو** لأنك تنشر نسخة جديدة لنفس عملية النشر، وليس عملية نشر جديدة.
12. اضغط **Done / تم**.

⚠️ لا تستعمل زر "New deployment / عملية نشر جديدة" لأن ذلك سينشئ رابط `/exec` مختلفاً، وستحتاج لتحديث `index.html` بالكامل.

## 2) اختبار سريع بعد النشر

1. افتح `index.html` (من استضافة حقيقية، ليس بفتح الملف مباشرة من القرص، حتى تعمل Hidden iframe بشكل صحيح).
2. عبّئ الفورم ببيانات تجريبية بهاتف مغربي صحيح (مثال: `0612345678`).
3. اضغط "أكد الطلب". يجب أن:
   - يتعطل الزر ويتغير نصه إلى "جاري تأكيد الطلب...".
   - تظهر رسالة النجاح بعد وصول تأكيد حقيقي من Apps Script.
   - يظهر سطر جديد في جدول `Orders` بنفس القيم، والعمود J = الكمية، والعمود K = رقم الطلب.
4. أعد إرسال نفس الصفحة (بدون تحديثها) للتأكد أن نفس order_id لا يكرر نفسه.
5. تحقق من Meta Events Manager (Test Events) أن حدث `Purchase` يظهر مرة واحدة فقط بعد التأكيد الحقيقي، وليس عند الضغط على الزر مباشرة.

## 3) نشر الصفحة (Frontend)

يمكنك رفع `index.html` + `style.css` + `script.js` + مجلد `assets/` إلى أي استضافة ثابتة (مثال: GitHub Pages، Netlify، Vercel، أو أي استضافة عادية). لا حاجة لأي معالجة على السيرفر من جهة الواجهة الأمامية.

## 4) ملاحظات مهمة

- لا يتم إطلاق `Purchase` إلا بعد تأكيد حقيقي من Apps Script يحتوي على `success: true` و`saved: true`، بعد أن يضيف Apps Script السطر فعلياً وينفذ `SpreadsheetApp.flush()`.
- المجموع يُحسب ويُعاد حسابه دائماً في Apps Script (`149 × الكمية`) ولا يُعتمد على القيمة القادمة من المتصفح.
- الكمية محصورة بين 1 و10 في الواجهة والسيرفر معاً.
- منع تكرار الطلبات مضمون على مستويين: `sessionStorage` في المتصفح، و`LockService` + بحث عن `order_id` في الشيت داخل Apps Script.
- الألوان والخطوط والتخطيط مطابقون للمواصفات المطلوبة (Mobile-first، RTL، بدون أي روابط تشتت الزبون).
